# Remove the FIT trusted CA on Linux

This procedure removes the mitmproxy Certificate Authority installed by FIT
from the system trust store. Use it to reset the environment before testing the
certificate installation flow again.

> This procedure applies to Debian, Ubuntu, and derived distributions that use
> `update-ca-certificates`.

## 1. Inspect the installed certificate

FIT installs its CA at this exact path:

```text
/usr/local/share/ca-certificates/fit-mitmproxy-ca.crt
```

Before removing it, confirm that the file exists and inspect its fingerprint:

```bash
sudo test -f /usr/local/share/ca-certificates/fit-mitmproxy-ca.crt \
  && sudo openssl x509 \
    -in /usr/local/share/ca-certificates/fit-mitmproxy-ca.crt \
    -noout -subject -fingerprint -sha256
```

If the command produces no output, the certificate file is not installed.

## 2. Remove the CA from the system trust store

```bash
sudo rm -- /usr/local/share/ca-certificates/fit-mitmproxy-ca.crt
sudo update-ca-certificates --fresh
```

The first command removes only the FIT CA. The second rebuilds the system CA
bundle and trust-store links.

## 3. Verify the removal

```bash
test ! -e /usr/local/share/ca-certificates/fit-mitmproxy-ca.crt \
  && echo "FIT CA removed from the system trust store"
```

To also confirm that the locally generated CA is no longer trusted, set
`FIT_USER_APP_PATH` to the same path used during the test and verify the
certificate generated by FIT:

```bash
openssl verify \
  "$FIT_USER_APP_PATH/mitmproxy/conf/mitmproxy-ca-cert.pem"
```

After removal, verification should fail with an error such as
`unable to get local issuer certificate` or `self-signed certificate`.

## Run the installation test again

Do not remove the files under `$FIT_USER_APP_PATH/mitmproxy/conf`. They contain
the local CA and its private key. On the next run, FIT will detect that this CA
is no longer trusted and request authorization to install it in the system
trust store again.

If `update-ca-certificates` is unavailable, do not use these commands. The
distribution uses a different trust-store mechanism and requires a dedicated
procedure.
